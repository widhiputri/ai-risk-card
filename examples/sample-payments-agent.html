Purpose and Usage

Intended Uses, Users and Domains
An AI agent used by the FI's corporate banking operations team to prepare and initiate outbound supplier payments on behalf of corporate clients who have delegated this task. The agent reads approved invoices from the client's accounts payable feed, matches them against purchase orders, checks the payee against the client's approved supplier list, and proposes a payment instruction.

Not intended for: payments to new or unapproved payees, cross-border payments to sanctioned or high-risk jurisdictions, payroll, or any payment the client has not delegated in its mandate.
Usage Guidance
The agent may only act within a signed client mandate. Every proposed payment is evaluated by the FI's runtime governance layer before execution. Operations staff must review every escalated payment within the review window. The agent must never be granted standing authority to change payee bank details.
TD

Techniques and Development

Main AI Techniques
Tool-using large language model agent. The model plans each task, calls FI-provided tools (invoice retrieval, purchase order lookup, supplier registry lookup, payment proposal) and emits a governance envelope for every proposed action. The model has no direct access to payment rails.
Architecture and Components
1. Planning layer: third-party LLM orchestrates the task and calls tools.
2. Tool layer: FI-owned APIs expose read access to invoices, purchase orders and the supplier registry, and a single write tool that submits a payment proposal.
3. Governance layer: every write is packaged as a governance envelope and evaluated by the FI's SAFR validator before it can reach the payments engine.
4. Execution layer: approved instructions are passed to the FI's existing payments engine and settle over the normal rails.
External AI Service Calls
LedgerFlow managed LLM API for planning and tool selection. Invoice and payment data sent to the API is limited to the fields needed for matching; client account numbers are tokenised.

Risks

3
▶ Payment above delegated authority Accountability & Governance
Mitigation Strategy
Per-payment and daily aggregate exposure limits are enforced by the governance layer, not by the agent. Payments above the autonomous threshold are escalated to a human reviewer; payments above the mandate ceiling are denied.
Appropriate Use Guidance
Exposure limits must be set to match the client's existing delegated authority matrix and reviewed whenever the mandate changes.
▶ Prompt injection via invoice content Cyber & Data Security
Mitigation Strategy
Invoice text is treated as untrusted data. The governance envelope is authenticated against the original invoice record, so an envelope whose payee or amount departs from the source invoice is denied regardless of what the agent reports.
Appropriate Use Guidance
Any new invoice source must be onboarded through the envelope integrity check before the agent can read it.
▶ Runaway or repeated actions Robustness & Stability
Mitigation Strategy
Rate limits cap the number of payment proposals per client per hour. Each step of a multi-step task is evaluated independently, so an approval at one step carries no authority into the next.
Appropriate Use Guidance
A rate-limit breach suspends the agent for that client until operations review the activity log.

Evaluation and Testing

2
Invoice-to-payment match accuracy
Measures whether the agent proposes the correct payee and amount for each approved invoice.
Result 99.6% (August 2026 evaluation)
▶ Methodology
2,000 historical invoices replayed in a sandbox. Each proposal compared with the payment a human operator made for the same invoice.
Escalation rate
Operational metric. Shows how much human review the agent generates, so escalation stays within reviewer capacity.
Result 6.8% of proposals (August 2026 pilot)
▶ Methodology
Escalated proposals divided by total proposals across the pilot clients. Alert threshold: above 12% triggers a threshold review.

Governance Envelope and Audit Log
Governance Envelope
Each proposed action carries the action type and parameters (payee, amount, currency, value date), the action trace (tool calls made, invoice and purchase order retrieved, supplier registry result, checks performed) and context metadata (agent identity, mandate reference, account state, operative policy). The envelope is authenticated against the source invoice record, not taken on the agent's word.
Audit Log
Append-only, tamper-evident log in the FI's compliance data store. Each entry records the envelope as submitted, the mandate checked, the disposition, the rules applied, the basis for the outcome and the time taken at each stage. Retained for 7 years and available to transaction monitoring and AML systems.
